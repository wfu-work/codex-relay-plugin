# 共享执行后端：第二阶段交付

日期：2026-09-10。范围：插件连接层、生命周期、授权后的实时订阅、状态诊断、控制台配置与生产构建。

## 已完成

- 抽出 `app-server-transport.js`，统一 JSONL stdio、WebSocket 和 Unix Socket 传输。
- 新增 `codex.connectionMode`（`managed` / `shared`）、`codex.appServerEndpoint`。已有配置默认迁移为 managed，不改变运行方式。
- shared 不执行 `codex --version`、不启动 Codex 子进程、不发送服务关闭命令。停止插件只关闭本连接；状态中的 `pid` 不会伪装成后端 PID。
- 连接断开后指数退避并加入抖动，最长 30 秒；重新执行 initialize 后恢复曾经授权的任务订阅。手动停止取消重连，旧连接的回调不能让已停止客户端复活。
- 未确认的命令不会重发。中断时拒绝在途 RPC，清理旧审批回执；共享连接恢复不会重放 turn.start。
- 保留原始快照/状态读取的只读语义；CommandRouter 校验项目访问权后才订阅共享任务。首次订阅后重读快照，避免旧 notLoaded 状态覆盖运行状态。后续轮询不重复 resume 或双倍读取。
- 后端断开会让事件重放产生明确缺口，客户端同步时需要快照补齐；事件序号保持递增。后端恢复状态通过 host.snapshot 发往 Relay。
- 后端暂不可用时仍保持 Relay 连接，远端可以看到后端正在重连。修改共享端点或访问范围会关闭旧连接及原订阅，再按新配置连接。
- 控制台高级设置新增后端模式与共享地址；总览新增连接方式、地址及后端错误。MCP 配置工具提供同样的非秘密配置项。
- 生产包内打包 ws 依赖，保持用户安装后无需另行 npm install；处理 ESM 构建中 ws 使用 Node 内置模块的兼容。

## 当前使用与边界

配置方法见仓库 README 的“共享执行后端”。shared 只连接已存在的服务；桌面也必须连接同一个服务。当前支持本机 ws/wss 和 Unix Socket，尚未提供 bearer token 字段。

正式安装缓存、运行中的桌面/Relay 配置和历史数据尚未切换。本次产物生成在仓库 `plugins/codex-relay-plugin`，没有提交或发布。

以下仍是后续阶段：桌面图标启动与常驻服务部署、原数据目录的备份和切换、跨进程命令回执持久化、完整断线历史补齐策略、两端队列界面、审批/用户问题归属、桌面专属工具兼容。第一阶段发现的桌面忽略 queue/changed 和立即停止的启动竞争仍需要后续处理。

默认值继续使用 managed。启用 shared 前，需要先准备统一后端以及桌面接入；它不会自动连接正在使用私有 stdio 的旧桌面进程。
