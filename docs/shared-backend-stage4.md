日期：2026-09-10。范围：插件与 Flutter 的交互请求、命令结果和事件恢复一致性。源码与生产插件已更新，本机未激活启动包已刷新；正式桌面尚未切换。

## 修复的问题

1. **旁观 Relay 会抢先拒绝桌面请求。** 用真实 Codex 0.153.4 和一个请求 MCP elicitation 的隔离工具复现：桌面准备接受时，原 Relay 已回复 `-32601`，工具得到 `decline`。共享模式现在对未知客户端请求保持旁观，由桌面处理；无任务身份的认证类请求不转发，未知 MCP 请求仅展示任务身份，不广播任意原始载荷。
2. **停止回执被当作执行终态。** Flutter 原来收到 `turn.interrupt` 回执就显示“已中断”。现在只显示停止已提交，等待对应轮次的终态事件或快照。插件按明确的 threadId / turnId 查询最近轮次，合并同时发来的停止请求，对“尚未开始执行”的窗口做有限重试；遇到新轮次不停止它，已正常完成的轮次保留完成状态。
3. **插件重启后可能重复执行写命令。** 新增持久命令日志，派发前落盘意图并同步到磁盘，结果随后原子写入；相同来源/请求/内容重试返回原回执。进程在派发后崩溃且无回执时，返回 `COMMAND_OUTCOME_UNKNOWN`，不重新执行。记录按 Relay 与后端连接隔离，指纹只存哈希，不保存提示词或问题答案；保留一天，入站命令有效期仍为五分钟。项目白名单和权限仍在回放时检查。
4. **事件序号不能跨插件进程比较。** 服务提供 `eventStreamId`；重连、后端配置切换、队列丢失时更新代际并使旧重放失效。异步等待的旧事件不能进入新流。快照先记录事件水位再读取目录，读目录期间的新事件仍可补发。Flutter 只按产品事件游标去重，不让事件缺口阻断命令回执；重放跳过已经消费的事件，缺口触发补齐，代际变化清理旧读取版本并强制重读当前任务。兼容未提供代际的旧插件，避免空快照循环。
5. **命令拒绝不代表现有任务失败。** Flutter 对结果未知、断线、写回执超时提示核对，不自动重发；新一轮发送被拒绝时重新读取真实任务状态，避免把桌面正在运行的轮次标成失败。

## 两端交互与输入

- 支持命令执行/文件修改审批，以及 `tool/requestUserInput` / `item/tool/requestUserInput`。每条请求使用独立公开 ID，后端原始 ID 保留类型；重连后的请求不会复用旧公开 ID。
- Flutter 的任务页新增交互卡片。审批展示命令、目录、原因和授权信息；问题支持选项、自定义回答、秘密字段遮挡和完整性校验。回答只保留在组件内存，不写入对话缓存。
- 卡片提交后等待后端确认；桌面先处理、后端自动解决、轮次结束或连接失效都会同步关闭。任务读取（含内容未变回执）携带待处理请求；客户端拒绝晚到的旧交互快照。
- 远程审批权限仍默认关闭。只读模式或未启用 `respondToApprovals` 时，Flutter 展示“请在桌面处理”。未知交互类型保持由桌面处理。
- 执行中可编辑草稿，增加“补充到当前任务”按钮，使用指定轮次的 `turn.steer`；停止按钮继续独立保留。补充内容确认接受后才清除，失败或结果未知保留草稿。草稿按连接与任务隔离。
- 本阶段没有增加共享队列 UI。官方桌面忽略 `thread/queue/changed` 的限制仍存在。
